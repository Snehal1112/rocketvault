# RocketVault Dashboard — Keys Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> for the multi-task breakdown below, or superpowers:executing-plans if executing
> this plan directly, top to bottom.

**Goal:** Cryptographic key lifecycle UI — list, create/import, view metadata/JWK,
crypto operations (sign/verify/encrypt/decrypt/wrap/unwrap), rotation + rotation
policy, versions, soft-delete/recover/purge, single-item backup/restore.

**Architecture:** See `docs/superpowers/specs/2026-09-08-webapp-dashboard-epics-design.md`
§§ 2, 6 (Epic 03). Vault-scoped only. Builds on Phase 0's `src/api/client.ts`,
`useAuth()`, the `vaults.$vaultName.tsx` layout route.

**Tech Stack:** unchanged from foundation.

**Conventions to follow:** see foundation plan §Conventions.

**Verification gate:**
```bash
cd web && bun run typecheck && bun run lint && bun run test && bun run build
```

`src/components/keys/key-list.tsx`, `key-create-dialog.tsx`, tests.

- [ ] **Step 1 (failing test):** `<KeyList>` table (name, type, tags,
      created) from `listKeys`. `<KeyCreateDialog>`: type select
      (RSA/EC/OCT) drives conditional fields (RSA → size select 2048/3072/4096;
      EC → curve select; OCT → bits select 128/192/256). **Do not
      pre-disable OCT based on a guessed HSM-enabled signal** — no confirmed
      client-visible flag for `hsm.enabled` exists. OCT stays selectable;
      write a test asserting a mocked `ErrOctKeysRequireHSM`-shaped 400/403
      from `createKey` renders the server's actual error message, not a
      generic failure.
  ```tsx

    vi.mocked(createKey).mockRejectedValue(

    )
    render(<KeyCreateDialog vaultName="prod" />)
    await selectKeyType("OCT")
    await submitForm()
    expect(await screen.findByText(/OCT keys require HSM/i)).toBeInTheDocument()
  })
  ```
