# v4.12.0 — OIDC JIT provisioning policy

> The version number is provisional and may change before tagging.

This release adds a policy for who may sign in through OIDC and turns
just-in-time (JIT) user provisioning off by default. It also adds PKCE to the
login flow and stops OIDC from provisioning on any lookup error. Full detail:
`docs/known-bugs.md` (B102, GitHub #70, and B103, GitHub #71). Key reference:
`docs/contributing/configuration.md` (OIDC login policy).

## What changed

- **JIT provisioning is off by default.** A new OIDC identity is created only
  when `oidc.jit_enabled: true`.
- **New policy keys under `oidc:`**
  - `jit_enabled` (default `false`): allow creating a user for a new identity.
  - `allowed_email_domains` (default `[]`): when set, the email domain must
    match one entry, case-insensitive, and the provider must send
    `email_verified: true`. A missing email is denied. Some providers (for
    example Microsoft Entra ID) do not send `email_verified` in ID tokens by
    default, so a domain list denies everyone there until the claim is
    configured.
  - `require_email_verified` (default `false`): the provider must report
    `email_verified` as true.
  - `required_claims` (default `{}`): each named claim must match the
    configured value; a claim holding a list matches when it contains it.
  - `default_role` (default `user`): role of a new user. Only `user` is
    accepted.
  - `enforce_on_existing` (default `true`): also apply the domain, verified
    and claim checks to already-linked users.
- **PKCE (S256) is always on** for the login flow. There is no switch.
- **Only "not found" creates a user.** Any other error while looking up the
  external identity is returned and no user is created.
- **Email is stored on OIDC users.** The new nullable `users.email` column is
  added by an automatic migration and refreshed at login.
- **A policy denial returns a generic 403.** The reason is written to the
  audit log only (`oidc_login_denied`).

## Breaking changes

1. **New OIDC identities are denied until you opt in.** Before, any identity
   the provider authenticated got a local user.

## Upgrade procedure

1. **To keep auto-provisioning, set `oidc.jit_enabled: true`** in
   `.rocketvault.yaml`. Consider also setting `allowed_email_domains` and
   `require_email_verified: true`.

   ```yaml
   oidc:
     jit_enabled: true
     allowed_email_domains: ["example.com"]
     require_email_verified: true
   ```

2. **Already-linked users keep logging in.** The policy checks apply to them
   when `enforce_on_existing` is `true` (the default), so a linked user who
   fails the domain, verified or claim checks is now denied. Set
   `enforce_on_existing: false` to exempt them.
3. Invalid policy values (a malformed domain, or a `default_role` other than
   `user`) make startup fail.
4. The `users.email` column is added automatically on SQLite and Postgres.
   No manual step.

## Schema

New nullable column `users.email`. It is dual-written in
`createOptimizedSchema` and `migrateSchema`. Identities still link only by
`(provider, subject)`, never by email.

## What did not change

Local username and password login, TOTP, and the `oidc.enabled` gate (default
`false`, no network call at startup) are unchanged.
